## Typography

Exactly 4 sizes and 2 weights in the admin UI. All from the existing `@theme` scale.

| Role | Size | Font / weight | Line height | Used for |
|------|------|---------------|-------------|---------|
| Meta | 12px (`text-xs`) | Geist Mono 400 | 1.55 | Section numbers ("01"), dates, slugs in tables, status badges, "Falta ES", "ES"/"EN" column tags, counters, version numbers, kbd |
| UI / Label | 14px (`text-sm`) | Hanken Grotesk 400 (body), 600 (labels, buttons, table headers, h2 of form sections) | 1.55 | Default admin text: tables, labels, inputs at ≥768px (existing `md:text-sm`), buttons, toasts, helper text |
| Body | 16px (`text-base`) | Hanken Grotesk 400; 600 for nav items and dialog titles | 1.55 | Inputs and textareas below 768px (prevents iOS zoom), rich text editor content, message reader body, empty-state headings |
| Heading | 25px (`text-xl`) | Funnel Display 600, `tracking-display` (-0.02em) | 1.1 | One H1 per page ("Proyectos", the project title in its form) |

Rules:
- Weights are 400 and 600 only. Geist Mono is always 400.
- Long-form text (textareas, editor, message body) is capped at 68ch (`max-w-[68ch]`).
- Numbers in tables and counters use `tabular-nums`.
- Text inside each ES/EN control is the content's own language: set `lang="es"` / `lang="en"` on the controls so spellcheck and screen readers use the right language.

### CV PDF typography (react-pdf, `assets/fonts-pdf/` static TTFs)

The PDF has its own contract because react-pdf only reads the static instances on disk. Exactly 2 weights in the PDF: 400 and 700. Geist Mono is always 400.

| Role | Size | Font / weight | Line height |
|------|------|---------------|-------------|
| Name | 20pt | Funnel Display Bold (700) | 1.1 |
| Section heading ("Experience" / "Experiencia") | 11pt | Funnel Display Bold (700) | 1.2 |
| Body, bullets | 9.5pt | Hanken Grotesk Regular (400) | 1.4 |
| Job titles, project names | 9.5pt | Hanken Grotesk Bold (700) | 1.4 |
| Meta (dates, contact line, stack) | 8.5pt | Geist Mono Regular (400) | 1.4 |

`Font.register` list (exactly these files, all verified present in `assets/fonts-pdf/`):
- `Funnel Display`: `FunnelDisplay-Bold.ttf` at `fontWeight: 700`
- `Hanken Grotesk`: `HankenGrotesk-Regular.ttf` at `fontWeight: 400`, `HankenGrotesk-Bold.ttf` at `fontWeight: 700`
- `Geist Mono`: `GeistMono-Regular.ttf` at `fontWeight: 400`

`FunnelDisplay-SemiBold.ttf` and `HankenGrotesk-Italic.ttf` stay on disk but are not registered or used in the CV (no 600 weight, no italic).

Page: A4 (210 × 297 mm), margins 18mm top/bottom, 20mm sides, one column, no photo, max 2 pages (D-04). Colors: ink `#171f2e` for text, ink-2 `#575e69` for meta, line `#dbd7d0` for 0.5pt section rules. No accent in the PDF (prints and ATS parsers read it as plain text). Hyphenation off (`Font.registerHyphenationCallback((w) => [w])`). Links (email, GitHub, LinkedIn, live URLs) are real PDF links, shown as plain text with the domain only.

Section order (Claude's discretion per CONTEXT): Name + headline → contact line (email · location, UTC offset · GitHub · LinkedIn · site) → Summary (SiteSettings bio, D-06) → Experience → Selected projects (`featured`, published, visible, D-05) → Skills (by category, featured first) → Education → Languages (CEFR).

## Color

DESIGN.md §3 tokens, already in `globals.css`. Hex values are sRGB conversions of the light theme for reference; the source of truth is the OKLCH value.

| Role | Token / value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--bg` oklch(0.985 0.006 80) ≈ `#fcfaf6` | Page background, form body, dialogs, inputs |
| Secondary (30%) | `--bg-elev` oklch(0.965 0.008 80) ≈ `#f6f3ee` | Sidebar, sticky page header, table header row, image frame while loading, badges, hover rows, `EnvMissingNotice` |
| Text | `--ink` ≈ `#171f2e` (15.8:1 on bg); `--ink-2` ≈ `#575e69` (6.3:1 on bg, 5.9:1 on bg-elev) | Primary text and the `default` button fill; secondary text, helper text, meta |
| Rules | `--line` ≈ `#dbd7d0` | Section rules, table row dividers, sidebar border, dashed upload frame |
| Accent (10%) | `--accent` terracotta oklch(0.66 0.17 40) ≈ `#e56636` | See reserved list. 3.2:1 on bg, so **never used for text below 24px** |
| Destructive | `--destructive` oklch(0.53 0.19 27) ≈ `#c22826` (5.6:1 on bg; white on it 5.8:1); dark oklch(0.70 0.17 25) **[NEEDS TEO]** | Field error text, `aria-invalid` borders, the final confirm button inside delete dialogs. Nothing else |
| Control border | `--input: color-mix(in oklch, var(--line), var(--ink-2) 60%)` (3.2:1 on bg) **[NEEDS TEO]** | Input, textarea, select, checkbox and switch outlines (WCAG 1.4.11). `--line` stays for rules and dividers |

Accent reserved for (exhaustive list):
1. The 2px vertical indicator next to the active item in `AdminNav` (non-text, 3.2:1 meets the 3:1 non-text minimum). The active item's label itself stays `--ink` at 600.
2. The focus ring (`--ring`, already wired system-wide; per-element state, not a "view" element).

Nothing else in the admin uses the accent: not buttons, not the publish CTA, not badges, not the unread counter, not links, not the section index, not toasts. This keeps DESIGN.md §3's "one element per view".

Status and state colors (no new hues):
- "Publicado": badge text `--ink`, background `--bg-elev`, 1px `--line` border.
- "Borrador": badge text `--ink-2`, transparent background, 1px dashed `--input` border.
- "Cambios sin publicar": badge text `--ink`, background `--bg-elev`, 1px dashed `--ink-2` border.
- "Oculto" (visible = false): row text `--ink-2` plus a mono "Oculto" badge. Never opacity below 1 on text.
- "Falta ES": mono 12px `--ink` on `--bg-elev`, 1px dashed `--ink-2` border, and the ES control gets a 1px dashed `--input` border while empty. Status is always text, never color alone.
- Unread messages: row name at 600 plus a mono "Nuevo" badge; nav counter is a mono badge `--ink` on `--bg-elev`.
- Draft Mode banner (public): `--ink` background, `--bg` text (inverted, no accent: the public page already spends its accent on the status line).

Forbidden here as everywhere: gradients, colored shadows, glassmorphism, any second accent hue.

## Accessibility Contract

- WCAG AA. Axe with no `serious`/`critical` on every admin screen (login, panel, each list, each form, CV, mensajes) and on the Draft Mode banner.
- Every icon-only button has an `aria-label` and a Tooltip with the same text.
- Focus is always visible: existing 2px `--ring` (accent) with 2px offset on `--bg`.
- Dialogs trap focus and return it to the trigger; AlertDialog default focus is the safe action (or the type-to-confirm input).
- Status is never color alone: every badge is text.
- The form-level error and toasts use live regions (Sonner's own `aria-live`; form error `role="alert"`).
- One `<h1>` per page; form sections are `<section aria-labelledby>` with `<h2>`.
- `lang="es"` on the admin `<html>` (existing); `lang` per ES/EN control.

## Open approvals [NEEDS TEO]

These touch palette or theme aliases, which CLAUDE.md says to ask about. None changes DESIGN.md's seven tokens.

1. **`--destructive` token** (DESIGN.md defines none; `text-destructive` in `login-form.tsx` currently resolves to nothing). Proposed light oklch(0.53 0.19 27), dark oklch(0.70 0.17 25); used only for field errors, invalid borders and the final delete button. Alternative if rejected: errors in `--ink` with a "Error:" text prefix and a 2px ink left rule (still AA, less scannable).
2. **`--input` alias** changed from `--line` (1.4:1, fails WCAG 1.4.11 for control boundaries) to `color-mix(in oklch, var(--line), var(--ink-2) 60%)` (3.2:1). Affects the public contact form in phase 4 too, which is desirable.
3. **Accent contrast**: the terracotta is 3.2:1 on `--bg`, so it fails AA for text under 24px. This spec uses it only as a 2px indicator and the focus ring in the admin. Phase 4 should check the hero status line and active links against this before building them.
4. **Admin light-only in phase 3** (Claude's discretion, low stakes): dark support can be added with the phase 4 theme script.
5. **CV paper size A4** for both locales (Claude's discretion): standard in Europe and accepted in Canada. Letter for EN is a one-line change if Teo prefers.
