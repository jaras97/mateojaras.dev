<objective>
Make missing pages answer a real HTTP 404 in the visitor's language: unmatched URLs through the approved catch-all (D-21) and unknown or draft project slugs through a proxy guard (D-06), verified first on the branch Preview.

Purpose: SITE-08 and the soft-404 reversal. With Cache Components the prerendered shell commits a 200 before an in-page notFound(), so only the proxy can decide the status (RESEARCH Summary). This is the phase's riskiest unknown on Vercel (A1 memo reuse, A2 status through a rewrite), so it ships first on the Preview, and each risky verification sits in its own small task.
Output: catch-all route, Preview-URL plumbing, guard + loader with unit tests, proxy change, not-found e2e with a production-write guard, flipped soft-404 assertions, decisions/backlog entries. The 404 UI itself is redesigned in 05-03.

Deviation from RESEARCH Pattern 1 (cold branch): RESEARCH let a cold memo fail open with a background load. That makes the first request on a fresh instance answer 200 for an unknown slug, which breaks D-06's "real HTTP 404" deterministically. This plan uses a bounded blocking load on a cold memo (fail open only on error or timeout) and keeps the background refresh for warm stale hits. Lighthouse is re-measured on the Preview in Task 3.
</objective>
