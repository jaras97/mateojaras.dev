## Pattern Assignments

### `src/features/*/actions.ts` (Server Action, CRUD write)

**Analog:** `src/app/admin/(panel)/actions.ts` (lines 1-13)

```typescript
"use server";

import { headers } from "next/headers";
import { redirect } from "next/navigation";
import { auth } from "@/lib/auth";
import { requireSession } from "@/lib/dal";

// Guarded first: without a session it redirects and never reaches signOut.
export async function signOutAction() {
  await requireSession();
  await auth.api.signOut({ headers: await headers() });
  redirect("/admin/login");
}
```

**What to copy:** `"use server"` at the top, `@/` imports, session check as the first statement, a one-line comment explaining the guard.

**What to change (RESEARCH Pattern 2, Anti-Patterns):** form actions must NOT use `requireSession()` (it redirects and loses unsaved edits). Use a new `requireActionSession()` from `src/lib/dal.ts` that returns `null`, then `return { ok: false, error: "session" }`. Order: session -> `schema.safeParse` -> Drizzle (`db.batch` for multi-statement writes, never `db.transaction`) -> `updateTag(...)` only for affected tags -> `after(() => exportContent({ db, tables: [...] }))`. Only `signOutAction` keeps the redirecting guard.

**Write via `db.batch`** (pattern from `src/lib/content-export.ts` lines 193-201 and `scripts/seed.ts` lines 142-162):

```typescript
const statements = [
  ...[...parsed].reverse().map(({ entry }) => db.delete(entry.table)),
  ...parsed
    .filter(({ rows }) => rows.length > 0)
    .map(({ entry, rows }) =>
      db.insert(entry.table as never).values(rows as never),
    ),
];
await db.batch(statements as never);
```

Use for publish (update columns + `draft = null` + delete/insert relation rows) and for reorder (one `update ... set order = i` per id).

**Updates with timestamp** (`scripts/seed.ts` lines 123-127):

```typescript
db.update(experiences)
  .set({ ...fact, updatedAt: sql`now()` })
  .where(eq(experiences.id, match.id))
```

(`base.updatedAt` also has `$onUpdate`, `src/db/columns.ts` lines 32-35, so explicit `sql\`now()\`` is optional.)
