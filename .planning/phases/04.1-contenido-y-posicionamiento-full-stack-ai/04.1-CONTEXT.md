## Existing Code Insights

### Reusable Assets
- Admin Server Actions per entity (`src/features/*/actions.ts`): the validated write path with `updateTag`. The load script should reuse the validation, and ideally the core write functions.
- `scripts/seed.ts` and `pnpm export:content`: an idempotent write pattern and a snapshot before changes.
- `generateCv` (Phase 3): regenerates the CV PDFs en/es into Blob plus `resume_versions`. `/resume.json` reads the same data.

### Established Patterns
- Paired `_en`/`_es` columns. Tiptap JSON for `now_*` and case-study rich text (static renderer on the public site).
- Published rows keep pending edits in `draft` jsonb. Publishing copies them to the columns. Structural fields (`visible`, `order`, `featured`) are written live.
- Metrics carry their source in the label (Phase 1 D-11).

### Integration Points
- Neon `main` (production) vs `dev` (preview/local). The script needs an explicit target and a dry-run.
- OG images and SEO metadata read `site_settings` and project fields, so they update automatically once the cache is invalidated.
