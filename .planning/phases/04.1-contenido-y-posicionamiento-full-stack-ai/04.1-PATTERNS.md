### `scripts/load-content.ts` (script, batch upsert)

**Analog:** `scripts/seed.ts`

**Header + imports pattern** (seed.ts L1-35). Usage comment block at the top, `@/` aliases, `createDb` from the unguarded client (never `@/db`, which imports `server-only`):
```ts
// Seeds docs/content into the database in DATABASE_URL.
// Usage: pnpm seed                         (refuses when a content table already has rows)
//        ...
//        --allow-production                (required when the target is Neon main or VERCEL_ENV=production)
import { readFileSync } from "node:fs";
import { count, eq } from "drizzle-orm";
import { createDb, type Db } from "@/db/client";
import { education, experiences, projects, SITE_SETTINGS_ID, siteSettings } from "@/db/schema";
import { loadContentDir } from "@/features/projects/content-file";
import { validateProjectContent } from "@/features/projects/content-schema";
import { projectRowFromContent } from "@/features/projects/seed-map";
import { describeDbTarget } from "@/lib/db-target";
import { requireEnv } from "@/lib/env";
import { assertNotProduction, assertSeedable } from "@/lib/seed-guard";
import { loadLocalEnv } from "./lib/env";
```

**Guard pattern** (seed.ts L74-84). Log only `describeDbTarget`, never the URL:
```ts
async function main() {
  loadLocalEnv();
  const url = requireEnv("DATABASE_URL");
  const target = describeDbTarget(url);
  console.log(`seed target: ${target}`);
  assertNotProduction({
    target,
    vercelEnv: process.env.VERCEL_ENV,
    allow: process.argv.includes("--allow-production"),
  });
  const db = createDb(url);
```
Add on top (RESEARCH "Target guard"): require `--target=dev|main`, compare with `target.startsWith(PRODUCTION_DB_ENDPOINT_PREFIX)` (`src/lib/seed-guard.ts` L16, value `"ep-billowing-union"`), abort on mismatch in either direction. `--apply` absent => print diff, exit 0.

Note: `loadLocalEnv` (`scripts/lib/env.ts` L5-11) never overrides an env var already set, so `DATABASE_URL='<main>' pnpm tsx ...` inline wins over `.env.local`.

**Project validation from docs/content** (seed.ts L92-97):
```ts
const files = loadContentDir("docs/content");
const rows = files.map(({ file, content }, index) => {
  const { issues } = validateProjectContent(content);
  if (issues.length > 0) throw new Error(`${file}: ${issues.join("; ")}`);
  return projectRowFromContent(content, index);
});
```
`projectRowFromContent` already omits `media` and `coverImage` (asserted in `seed-map.test.ts` "never seeds the cover image or media"). The loader then re-validates with `projectPublishSchema`, passing the target row's existing `media`/`coverImage` through so the cover rule (`validation.ts` L107-117) holds.

**Batch write pattern** (seed.ts L153-167). Neon HTTP: no `db.transaction`, one `db.batch` per group:
```ts
const [first, ...rest] = [
  db.insert(siteSettings).values(settingsRow).onConflictDoNothing({ target: siteSettings.id }),
  ...rows.map((row) => db.insert(projects).values(row).onConflictDoNothing({ target: projects.slug })),
  ...experienceStatements,
  ...educationStatements,
];
await db.batch([first, ...rest] as never);
```
The loader replaces `onConflictDoNothing` with select-by-natural-key then `update(...).set({...text, status: "published", draft: null}).where(eq(id))` or `insert`. Typed variant from `projects/actions.ts` L25, L65-67:
```ts
type BatchItem = Parameters<typeof db.batch>[0][number];
function runBatch(items: BatchItem[]) {
  return db.batch(items as [BatchItem, ...BatchItem[]]);
}
```
In the script use `Parameters<Db["batch"]>[0][number]` with `Db` from `@/db/client`.

**Relation replace pattern** (projects/actions.ts L51-63; experience/actions.ts L45-73): delete + insert in the same batch as the parent update:
```ts
function replaceSkills(id: string, skillIds: string[]): BatchItem[] {
  const items: BatchItem[] = [db.delete(projectSkills).where(eq(projectSkills.projectId, id))];
  if (skillIds.length > 0) {
    items.push(db.insert(projectSkills).values(skillIds.map((skillId) => ({ projectId: id, skillId }))));
  }
  return items;
}
```
Ordering constraint: `projectDraftSchema.skillIds` is `z.array(z.uuid())` (validation.ts L78), and experiences take `skillIds` + `projectIds`. Skills must be upserted first (batch 1), ids read back by `name`, then projects (batch 2, new rows `.returning({ id })` or re-select by `slug`), then experiences and relations (batch 3).

**Error/exit pattern** (seed.ts L183-186):
```ts
main().catch((error) => {
  console.error(error instanceof Error ? error.message : "seed failed");
  process.exitCode = 1;
});
```

**Do NOT copy:** `seedAdmin` (L59-72). The loader never touches auth tables. Do not import any `actions.ts` (`"use server"`, `@/db` -> `server-only`, `@/lib/dal` -> `next/headers`).

### `src/lib/content-lint.ts` (pure checks) and test

**Analogs:** `scripts/check-phase-3.ts` L29-60 (markers + recursive string walk) and `src/features/projects/content-schema.ts` L201-278 (`stringsIn`, `digitTokens`, `checkNumberParity`).

**Marker regex + string collector** (check-phase-3.ts L29-51):
```ts
// TODO is matched as an uppercase word: the Spanish word "Todos" is real copy.
const MARKERS = /\[Teo escribe\]|\bTODO\b|lorem/;
function collectStrings(value: unknown, out: string[] = []): string[] {
  if (typeof value === "string") out.push(value);
  else if (Array.isArray(value)) for (const v of value) collectStrings(v, out);
  else if (value && typeof value === "object") for (const v of Object.values(value)) collectStrings(v, out);
  return out;
}
```
**Digit parity** (content-schema.ts L237-241 doc comment + L242-278): reuse the multiset approach for every en/es pair (settings, experience bullets, education status), not only projects. Consider exporting `digitTokens`/`surplus` from content-schema rather than duplicating.

Patterns to add (RESEARCH Pitfall 5): U+2014 em-dash, prices (`COP`, `USD`, `$`, `millones`), infra ids (`fly.dev`, `supabase.co`, Prendo `.vercel.app`), markers. Must stay pure (no `server-only`, no `node:fs`) so both loader and check script import it.

**Test pattern** (`src/lib/seed-guard.test.ts` L1-40): `describe`/`it` with `toThrow(/regex/)` and named fixtures:
